# Retain originals and review extracted orders

In **Sales orders → Evidence documents and extracted orders**, the owner uploads a PDF, PNG or JPEG original. The bounded format checks reject active or encrypted PDF content, embedded files, malformed images and mismatched file signatures. Originals are at most 1 MiB; PDFs use conventional page objects, without object streams, and contain up to 40 pages. A duplicate's bytes resolve to the retained original. Originals and their hashes remain private; no upload changes stock or creates an order.

**Document processing consent** is separate from item-agent consent. The owner selects an exact OpenAI model and authorizes the fixed Responses destination. Each **Extract cited draft** request separately confirms sending that entire original. The API key is encrypted and excluded from reads/exports. A changed installation signing key requires a new connection. Requests are claimed durably before egress and uncertain paid requests are not retried automatically.

The extracted draft includes source-page quotations and pack ambiguity flags. Treat every source instruction as untrusted business text. Read the original, select the actual customer and SKU, correct quantities, packs, prices, dates and address, and record a reason. **Preview corrected order** shows the route, warehouse and customer prices without creating an order or reservation. **Approve reviewed order once** creates only that exact reviewed version. Changed prices, stock, routing or UTC day require a fresh preview. Duplicate originals and customer PO references cannot create another order.

To receive originals by email, configure **Signed document inbox** with a receiving address you control and its SendGrid Inbound Parse verification public key. The receiving endpoint is `/api/pier/documents/inbound`. It admits only verified, bounded mail addressed to that inbox. Its text and safe attachments stay private for review; it never infers customer identity, starts extraction, replies, reserves stock or posts money automatically. Configure a dedicated provider endpoint; do not repoint another application's webhook.

The adopted default is owner-only access, separate explicit full-original processing consent, signed inbox consent, a fixed model destination and retained originals without an erase door. This privacy/retention default awaits ct approval. DATA-001/002 retain complete archive, retention and erasure obligations; SEC-002 retains wider attachment and connector egress obligations. No live receiving-domain receipt is claimed by the network-edge tests.

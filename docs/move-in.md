# Move into Pier from Cin7 Core, inFlow or Fishbowl

Use **Imports → Move from your inventory system** to prepare a cutover without posting stock. Select the system, retain its export files, map the columns, and upload independent stock controls. Preview shows source rows, native mappings, unsupported columns, items/SKUs, bins, on-hand quantities, cost evidence, customers, suppliers and remaining purchase/sales lines. A SKU variant becomes a separate stock item; family/group labels remain in the retained export unless already part of the product name.

These adapters use explicit field maps because vendor editions and configurable report layouts differ. The three synthetic fixtures prove the documented layouts below through authenticated Worker/D1 commands. They are authored test data, not an owner's export. Production cutover still needs the owner's authorized export, source reconciliation and exact frozen approval. This does not establish all of MIGRATE-001 or imported history under MIGRATE-002.

## Prepare the source

Freeze a specific cutoff, timezone, source version and export filters. Keep the old system read-only during final reconciliation. Preserve the original external archive as well as every submitted CSV. Pier retains the exact UTF-8 CSV bytes, SHA-256, file names and source row numbers. When converting a vendor Excel report to CSV, record that conversion in the source version/filters and retain the original workbook separately; Pier does not ingest XLSX here.

| System | Documented export surfaces and interpretation |
| --- | --- |
| Cin7 Core | Inventory/party CSV exports; configurable Product Availability and Product Stock Level reports; Purchase Order Details report. Reports export to Excel, so a selected-column report needs a documented UTF-8 CSV conversion. Map the **on-hand** quantity, not available or allocated. Map Unit Cost as a per-base-unit USD value. Purchase Order Details Quantity is ordered quantity: use only independently checked wholly unreceived lines, or provide reviewed remaining-line evidence. |
| inFlow Inventory | Export Product Details, Stock Levels, Customers, Vendors and Purchase Orders separately. ProductName is the source product identity; SKU can differ. Stock levels refer to ProductName and contain Location/Sublocation. Uom and Cost can join from Product Details by exact source key. The order export does not establish how much was received: this adapter rejects processing states other than Unfulfilled. Supply reviewed remaining-line evidence for partial receipts. |
| Fishbowl Warehouse | Part, Inventory Quantities, Location and party exports. Keep the full inventory Location string, including its location-group prefix. Inventory Qty is on hand; Cost is per UOM. The native PO export has separate PO and Item sections. Select that layout rather than flattening the raw file. Only issued PO status 20 and purchase item type 10 are admitted. Map PartQuantity minus FulfilledQuantity to expected receipts. |

## Map without guessing

Every file has a content type and an explicit target-field-to-source-column map. Column order is flexible; spelling and case are exact. The preview names a missing mapped column, an unknown target field, an unmapped column, duplicate identity, malformed row or unresolved reference. Every unmapped source column needs a specific archive reason before review can advance. A whole unsupported file can use **Retain unsupported records**, with a reason; its original and rows stay linked to the batch without creating stock.

- Items require stable key, SKU, name, base unit and explicit packSize. Barcodes remain text, preserving leading zeros. Optional openingCost supplies stock unit cost through an exact item-key join. Base quantities are never interpreted as packs.
- Locations use a stable source key, display name, warehouse and bin/transit kind. Alternatively, stock rows can explicitly map warehouse and bin; Pier derives a unique `[warehouse, bin]` source key and creates those bins once. Controls must use that same identity or map the same warehouse/bin pair. No location name is split or guessed from punctuation.
- Suppliers and customers use their source key/name. Their internal source identities are separated by party type, allowing a customer and supplier with the same source identifier.
- Stock needs itemKey, locationKey, status, quantity, unit and cost. Unit can join from the mapped item; cost can join from its explicitly mapped openingCost. If no stock key exists, the defined identity is itemKey + locationKey + status. Repeated openings for that identity are rejected; lots cannot be silently collapsed.
- Open document lines require a containing document key, counterparty key, item key, remaining quantity, unit and explicit promise date; purchase lines also require price. Select whether quantity is already remaining or ordered less fulfilled. Stable line IDs are preferred. If the export has none, explicitly select **Document + original line order** and preserve that order on revisions. Fishbowl provides `@line` with the same document/ordinal identity. Reordering lines can therefore require reviewed replacements.
- Dates accept ISO YYYY-MM-DD, or an explicitly selected M/D/YYYY conversion. Currency is explicitly USD; recognized non-USD source currency fields are rejected. No FX rate, unit conversion, base unit, pack size, promise date or cost is invented.

The adapter does not create live tracked inventory from populated lot/serial fields. A tracked export must be reconciled separately, not stripped to look untracked. Exact native allocations are supported by the separate native CSV kit; these incumbent adapters do not reconstruct source allocation IDs or bin priority.

## Reconcile before applying

Submit a separate, independently checked report with one row per bin and base unit: locationKey, unit, quantity and USD value. You can map any actual report column names to those four fields. Its file digest must differ from the opening-stock artifact. A separate file alone does not prove independent preparation: the owner must compare it to the vendor report and the physical/accounting cutoff.

Pier independently sums mapped opening quantities and quantity × unit cost by bin/base unit, using integer arithmetic with six-place quantities/costs and twelve-place extended values. Every group requires a control; duplicate controls, missing groups, unknown units, different quantities and different values block review. Unlike units are never summed. Empty openings still require an explicit zero control. Control values are source evidence, not a general-ledger close or accounting reconciliation.

Review proceeds captured → mapped → reconciled → shadow → frozen. Material stock/document changes invalidate the preview. Apply uses the existing atomic native import journal: items, parties, bins, openings, open documents and the durable command result publish together or remain unchanged. Resubmit the same source identities/content to get a no-op; changed rows require explicit replacement and fresh review. The original command identity resumes interrupted publication.

**Undo accepted batch** checks dependencies and restores prior native rows in one command while retaining source custody. Later movements, counts, native edits or dependent reservations/documents prevent unsafe undo. Reconcile those differences through the corresponding operational correction.

Opening values enter USD operational valuation. These adapters use cutover posting dates for opening layers; original FIFO receipt ages are not reconstructed. Source layer dates, terms, taxes, sales prices, reorder/routing settings, credits, invoices, payments, tracking, attachments, manufacturing and transaction history remain unsupported unless covered by another explicitly reviewed flow. Account for them in the archive coverage review. There are no outbound vendor API calls or supplier/customer messages.

## Reproducible local evidence

`tests/fixtures/movein/{cin7-core,inflow,fishbowl}/` contains synthetic source CSVs, independent controls and an explicit `mapping.json` for each format. The fixtures include SKU variants, two warehouses, fractional units, leading-zero barcodes, customers, suppliers and grouped open POs. The three public Worker/D1 tests in `tests/api/movein.test.mjs` cover source custody/coverage, missing columns, duplicate/orphan rows, control-value refusal, review/apply, replay and safe undo. The Cin7 case also interrupts SQL publication and proves no partial business rows exist before resumption.

Run `node --test --test-concurrency=1 tests/api/movein.test.mjs` in an installed checkout. Browser inspection and real-owner/vendor/accounting acceptance are separate evidence boundaries.

Books catalogue and valuation snapshots remain as immutable evidence after an otherwise unused cutover is undone. They do not consume stock or create an accounting obligation. Later stock work, reservations and financial documents still block undo. Payment readback alone does not invalidate an unchanged stock preview.

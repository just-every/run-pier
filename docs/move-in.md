# Move into Pier from Cin7 Core, inFlow or Fishbowl

Use **Imports → Move from your inventory system** to prepare a cutover without posting stock. Select the system, retain its export files, map the columns, and upload independent stock controls. Preview shows source rows, native mappings, unsupported columns, items/SKUs, bins, on-hand quantities, cost evidence, customers, suppliers and remaining purchase/sales lines. A SKU variant becomes a separate stock item; family/group labels remain in the retained export unless already part of the product name.

These adapters use explicit field maps because vendor editions and configurable report layouts differ. The three synthetic fixtures prove the documented layouts below through the signed-in import workflow. They are authored test data, not an owner's export. Production cutover still needs the owner's authorized export, source reconciliation and exact frozen approval. This does not establish all of MIGRATE-001 or imported history under MIGRATE-002.

## Prepare the source

Freeze a specific cutoff, timezone, source version and export filters. Keep the old system read-only during final reconciliation. Preserve the original external archive as well as every submitted CSV. Pier retains the untouched UTF-8 CSV files, file fingerprints, file names and source row numbers. When converting a vendor Excel report to CSV, record that conversion in the source version/filters and retain the original workbook separately; Pier does not ingest XLSX here.

| System | Documented export surfaces and interpretation |
| --- | --- |
| Cin7 Core | Inventory/party CSV exports; configurable Product Availability and Product Stock Level reports; Purchase Order Details report. Reports export to Excel, so a selected-column report needs a documented UTF-8 CSV conversion. Map the **on-hand** quantity, not available or allocated. Map Unit Cost as a per-base-unit USD value. Purchase Order Details Quantity is ordered quantity: use only independently checked wholly unreceived lines, or provide reviewed remaining-line evidence. |
| inFlow Inventory | Export Product Details, Stock Levels, Customers, Vendors and Purchase Orders separately. ProductName is the source product identity; SKU can differ. Stock levels refer to ProductName and contain Location/Sublocation. Uom and Cost can join from Product Details by exact source key. Description supplies the product name in Pier; ProductName remains the source identity. Only untracked stockable products with a SKU are supported. The public purchase-order sample has no fulfilled-quantity column: only wholly unfulfilled lines can be read directly. For partial receipts, explicitly map ordered and fulfilled quantities from independent source evidence. Purchase quantities and prices must already be in the product’s base unit; no purchase-pack conversion is guessed. |
| Fishbowl Warehouse | Part, Inventory Quantities, Location and party exports. Keep the full inventory Location string, including its location-group prefix. Inventory Qty is on hand; Cost is per UOM. The native PO export has separate PO and Item sections. Select that layout rather than flattening the raw file. Only issued PO status 20 and purchase item type 10 are admitted. Map PartQuantity minus FulfilledQuantity to expected receipts. |

## Map without guessing

Every file has a content type and an explicit target-field-to-source-column map. Column order is flexible; spelling and case are exact. The preview names a missing mapped column, an unknown target field, an unmapped column, duplicate identity, malformed row or unresolved reference. Every unmapped source column needs a specific archive reason before review can advance. A whole unsupported file can use **Retain unsupported records**, with a reason. For a mixed file, open **Retain individual unsupported rows without importing them**, choose the CSV row number and give a reason. The preview lists each retained-only row and reason. Its original stays linked to the batch and creates no stock or open document. Related rows in other files must still reconcile; excluding a product does not silently exclude its stock or orders.

- Items require stable key, SKU, name, base unit and explicit packSize. Barcodes remain text, preserving leading zeros. Optional openingCost supplies stock unit cost through an exact item-key join. Base quantities are never interpreted as packs.
- Locations use a stable source key, display name, warehouse and bin/transit kind. Alternatively, stock rows can explicitly map warehouse and bin; Pier derives a unique `[warehouse, bin]` source key and creates those bins once. Controls must use that same identity or map the same warehouse/bin pair. If your source has no sublocations, enter **Bin name for blank source sublocations** on the stock file, for example `Main stock`. That name fills only blank bin cells and leaves named sublocations unchanged. Use the same name in the independent stock check (or enter it on the check file too when its bin cells are blank). No location name is split or guessed from punctuation.
- Suppliers and customers use their source key/name. Their internal source identities are separated by party type, allowing a customer and supplier with the same source identifier.
- Stock needs itemKey, locationKey, status, quantity, unit and cost. Unit can join from the mapped item; cost can join from its explicitly mapped openingCost. If no stock key exists, the defined identity is itemKey + locationKey + status. Repeated openings for that identity are rejected; lots cannot be silently collapsed.
- Open document lines require a containing document key, counterparty key, item key, remaining quantity, unit and explicit promise date; purchase lines also require price. Select whether quantity is already remaining or ordered less fulfilled. Stable line IDs are preferred. If the export has none, explicitly select **Document + original line order** and preserve that order on revisions. Fishbowl provides `@line` with the same document/ordinal identity. Reordering lines can therefore require reviewed replacements.
- Dates accept ISO YYYY-MM-DD, or an explicitly selected M/D/YYYY conversion, optionally followed by a valid 24-hour time such as `14:18` or `14:18:00`. Pier keeps the calendar date without a timezone shift and preserves the original date/time. A blank RequestedShipDate is not a promise: select a source column that actually contains the agreed fulfilment date, or enter an explicitly reviewed fixed date. Do not substitute a payment due date without checking what it means. Currency is explicitly USD; recognized non-USD source currency fields are rejected. No FX rate, unit conversion, base unit, pack size, promise date or cost is invented.

The adapter does not create live tracked inventory from populated lot/serial fields. A tracked export must be reconciled separately, not stripped to look untracked. Exact native allocations are supported by the separate native CSV kit; these incumbent adapters do not reconstruct source allocation IDs or bin priority.

## Check an inFlow export before approval

The importer states its supported subset on the upload page. The vendor’s public examples contain non-stocked/service products, serial tracking, blank SKUs or sublocations, negative balances, completed/cancelled purchases and purchase units such as boxes. They are examples of source layouts, not a ready-to-post company opening snapshot.

Keep every original. Name a real destination bin for blank sublocations using the field above. Retain unsupported rows with individual reasons, and check related product/stock/order rows together. Resolve negative balances in the source or a separately reconciled correction; do not turn them into zero stock. Map an actual promise date and positive remaining quantity. A purchase unit different from the product’s base unit needs reviewed conversion of both quantity and price before import, or explicit retention without creating expected stock. Pier reports the file and row rather than inventing these values. Build the independent stock check for the exact supported opening subset you intend to approve.

## Reconcile before applying

Submit a separate, independently checked report with one row per bin and base unit: locationKey, unit, quantity and USD value. You can map any actual report column names to those four fields. Its file digest must differ from the opening-stock artifact. A separate file alone does not prove independent preparation: the owner must compare it to the vendor report and the physical/accounting cutoff.

Pier independently sums mapped opening quantities and quantity × unit cost by bin/base unit, using integer arithmetic with six-place quantities/costs and twelve-place extended values. Every group requires a control; duplicate controls, missing groups, unknown units, different quantities and different values block review. Unlike units are never summed. Empty openings still require an explicit zero control. Control values are source evidence, not a general-ledger close or accounting reconciliation.

Review proceeds captured → mapped → reconciled → shadow → frozen. Material stock/document changes invalidate the preview. On approval, items, parties, bins, openings and open documents save together. A refusal leaves the business records unchanged. Resubmit the same source identities/content to get a no-op; changed rows require explicit replacement and fresh review. The original command identity resumes interrupted publication.

**Undo accepted batch** checks dependencies and restores prior native rows in one command while retaining source custody. Later movements, counts, native edits or dependent reservations/documents prevent unsafe undo. Reconcile those differences through the corresponding operational correction.

Opening values enter USD operational valuation. These adapters use cutover posting dates for opening layers; original FIFO receipt ages are not reconstructed. Source layer dates, terms, taxes, sales prices, reorder/routing settings, credits, invoices, payments, tracking, attachments, manufacturing and transaction history remain unsupported unless covered by another explicitly reviewed flow. Account for them in the archive coverage review. There are no outbound vendor API calls or supplier/customer messages.

## Reproducible local evidence

`tests/fixtures/movein/{cin7-core,inflow,fishbowl}/` contains synthetic source CSVs, independent controls and an explicit `mapping.json` for each format. The fixtures include SKU variants, two warehouses, fractional units, leading-zero barcodes, customers, suppliers and grouped open POs. The three signed-in API integration tests in `tests/api/movein.test.mjs` cover source custody/coverage, missing columns, duplicate/orphan rows, control-value refusal, review/apply, replay and safe undo. The Cin7 case also interrupts SQL publication and proves no partial business rows exist before resumption.

# Connect sales channels

Open **Channels** in Pier. The owner chooses a connection warehouse and can activate reviewed source routing, reviews unmatched listings and sees each channel's available and accepted stock quantities. Other roles can read these records. Shopify and Amazon connect when the owner's merchant accounts exist; their documented API adapters are exercised with synthetic recorded JSON fixtures at the network edge, not accepted live accounts. There is no fixture mode in the application.

## Choose your platform

Each connection form includes its account requirements and the menu paths for every credential. Follow the complete platform guide:

- [Connect Stall](stall.md): create Stall's agent credential, then paste Pier's scoped key into Stall's Settings.
- [Connect Shopify](shopify.md): authorize your custom app, enter its client credentials and select the store location by name.
- [Connect Amazon](amazon.md): register and authorize an SP-API app, select the marketplace country and provide renewable authorization.
- [Connect WooCommerce](woocommerce.md): create a read/write REST API key and optionally add signed order webhooks.

Create your Pier warehouse bins before connecting. The warehouse and stock buffer are your choices; neither creates stock. With **Enable this connection** selected, saving starts normal synchronization, so review the selected warehouse and availability first.

## Orders and availability

Pier reads live fulfilment demand through WooCommerce REST `wc/v3`, Shopify Admin GraphQL `2026-10` and Amazon SP-API Orders `2026-01-01`. Products and variants keep their existing provider identities. Matching uses an existing mapping first and then an exact SKU; an unknown SKU waits for the owner to select an existing Pier item. Mapping creates no provider listing. An order with an unknown line or unsupported currency waits without reserving any of its lines. Pier currently accepts USD orders only.

Imported demand follows its active source routing rule, or the connection's selected warehouse when no rule exists and uses Pier's normal atomic reservation command. Repeated notifications and reconciliation link the same channel order to the same Pier order. Click the order reference to inspect its reserved and backordered lines. Listings found only on an order can be matched for that order, but stock cannot be published until the provider returns an actual listing.

Available stock is sellable stock in the rule’s eligible warehouses (or the selected fixed warehouse), minus order reservations, active transfer holds and the channel's stock buffer. Holds allocate actual unreserved units to bins: ordinary orders, transfers and count adjustments cannot consume them. Add a hold with an item, warehouse, quantity and plan/reason, for example “100 held for FBA transfer”. Release it when the separate physical transfer is ready; this hold is not an Amazon inbound shipment or an FBA inventory ledger.

After a committed stock or reservation change, Pier immediately synchronizes connected channels. A one-minute cron reconciles missed events and pending publication. **Sync now** uses that same transport. The listing shows the accepted quantity, acceptance time and request duration. Pending changes show elapsed lag; failures remain visible and never pretend an update was accepted. An installation-wide lease serializes publication so two connector runs cannot overtake each other. Rate limits, API failures and large backlogs can exceed one minute and need attention; this is not a measured production 95th-percentile service guarantee. Amazon's acceptance is asynchronous submission acceptance, not proof that Amazon has finished processing it.

Shopify publication retains its target, quantity, routing revision and idempotency identity before sending. **Location outcomes** preserves accepted and uncertain results, including earlier mappings and stock frontiers. **Sync now** reads provider stock before recovery: an already accepted quantity is confirmed without another mutation. A changed mapping or revoked approving owner invalidates pending authority; no default location is substituted. Reauthorize the connection or activate a fresh current-owner rule before work resumes. These protocol journeys supply no live merchant account qualification.

## Stall

Stall is the online shop from the same family; it sells from Pier's stock. No Stall yet? Start one on this computer with `rer dev just-every/run-stall` ([Run Stall and Pantry beside Pier](run-beside.md)). The connection has two halves, both made from the two apps' own pages:

1. **Pier reads Stall.** In Stall, open **Settings → Agent access** and choose **Create agent credential**. In Pier, open **Channels → Connect** on the Stall card, enter Stall's address (from its browser tab, for example `http://localhost:8791`), choose the warehouse, paste the credential as **Access token** and choose **Connect store**. Stall's agent credentials last seven days; when Pier reports that Stall refused access, create a new one in Stall and use **Manage → Replace credentials** in Pier.
2. **Stall reads Pier.** On the Stall card in Pier, choose the customer Stall's orders belong to (or **Add “Online shop (Stall)”**, which creates that customer and selects it) and choose **Create Stall's key to Pier**. Pier shows its address and the key once and keeps only a fingerprint of the key. In Stall, open **Settings → Provider connections** (Stall's address followed by `/app#settings`), paste both into **Connect Pier** and choose **Connect Pier**; Stall checks the key with Pier and shows **Connected**. This is the same for a Stall on this computer and a Stall online: no files and no restart. Creating a new key stops the old one at once (paste the new one in Stall); **Remove Stall's key** stops Stall reaching Pier.

The key lets Stall do only what a shop does: read stock and its own customer's orders, reserve that customer's paid orders and dispatch them. It is not a person's sign-in and cannot change anything else in Pier. Stall takes payments through Stripe on your own Stripe account: connect it on the same Stall page (**Connect Stripe**, test keys first). Publish a product in Stall whose SKU matches a Pier item; a paid Stall order then appears under **Channels → Orders**, reserved in Pier. A Stall on your own computer cannot receive Stripe's payment notice, so after a test payment open the order in Stall and choose **Reconcile**.

A paid Stall checkout creates its reservation directly in Pier. The connector links that reservation by its Pier identity and does not reserve the order again. Stock publication is a read-back from Stall's live catalogue, which itself reads Pier. Stall’s scoped key reads only its source’s eligible warehouse positions, net of reservations, holds and its buffer. The paid reservation follows that same source rule. A differing read-back is shown as a failure rather than silently accepted. Stall's original payment, shipping approval and native-session requirements remain in force.

## Account setup

[WooCommerce](woocommerce.md) uses a key created at **WooCommerce → Settings → Advanced → REST API → Add key**, with **Read/Write** access. The optional webhook secret is a password you choose and enter identically in Pier and each WooCommerce webhook's **Secret** field so Pier can verify the sender. Without reachable webhooks, the minute reconciliation still reads processing orders. Refunded orders remain outside the supported live-demand profile.

[Shopify](shopify.md) requires your permanent `myshopify.com` store address, a custom app with product/order/inventory/location scopes, client credentials and a location selected from the store. New apps use Shopify's Dev Dashboard; Pier exchanges their client credentials for API access automatically. The app and installed store must be in the same Shopify organization. Existing legacy custom apps retain an explicit Admin API token mode. The stock adapter uses compare-and-swap inventory updates with idempotency keys. Rule-based routing can publish a pooled eligibility quantity to the configured provider location. In Sales orders → Settings → Warehouse routing rules, channel-location mode maps each exact Shopify location identity to one Pier warehouse. After the current owner previews and activates the rule, each mapped location receives that warehouse’s eligible availability less its reservations, protected holds and the connection buffer. The Listings table keeps a separate quantity and outcome for each location without changing the listing or imported order identities. Multiple or missing assigned Shopify fulfilment locations wait rather than being guessed.

[Amazon](amazon.md) requires an approved SP-API developer/app registration and seller authorization. Choose the marketplace by country; Pier supplies its ID and regional address. Supply the seller ID and LWA refresh token, client ID and client secret for automatic access-token renewal. The adapter reads merchant-fulfilled open orders and existing seller-SKU listings; FBA-only inventory is not published here.

Provider credentials are encrypted under this installation's session secret in a separate server-side table. They are absent from business exports, command results and portable archives. Re-enter them after restoring or changing the installation secret. Connection forms do not persist credential payloads in browser storage. Pause a connection to stop automatic traffic; revoking its approving owner's authority stops scheduled admission too.

Full cancellation/refund and fulfilment write-back, historical backfill, financial clearing, FBA shipment/report reconciliation, additional channels and production throughput acceptance remain in CHANNEL-001 to CHANNEL-006. Existing imported orders are not inferred cancelled merely because they disappear from a provider's live-order list.

API references: [WooCommerce REST](https://woocommerce.github.io/woocommerce-rest-api-docs/), [Shopify inventorySetQuantities](https://shopify.dev/docs/api/admin-graphql/2026-10/mutations/inventorySetQuantities), [Amazon Orders](https://developer-docs.amazon/sp-api/reference/searchorders), [Amazon Listings Items](https://developer-docs.amazon/sp-api/reference/patchlistingsitem).
